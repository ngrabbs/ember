# Payload carrier pin plan — next prototype

2026-10-04. This plan replaces the [May legacy map](payload_carrier_pinmap_legacy_2026-05.md)
for the next carrier. See [schematic-start baseline](schematic_start.md).
It records functional module pin reservations; connector symbol/pad maps and
module variant acceptance are required before placing or wiring the real parts.
No legacy PCB connectivity was changed by this document.

Use NVIDIA DG-10931-001 v1.5, especially tables 6-1, 9-1 and 10-2, and
[the saved guide](Jetson_Orin_Design_Guide_DG-10931-001_v1.5.pdf).
The [system CSKB map](../../../system/interfaces/cskb_pinmap.md) owns H1/H2 numbering.
Direction names below are from the module's perspective.

## Module power and control

| Module pins | Function | New carrier interface |
|---|---|---|
| 251–260 | VDD_IN | Fixed local +5V_ORIN, all ten contacts; actual load/transient and connector allocation to qualify |
| 217 | MODULE_ID | Inventory exact module; 5 V-only design, do not infer SD boot from mechanical fit |
| All documented GND pins | GND | Complete socket map and continuous return plane; verify against exact symbol |
| 237 | POWER_EN, input | Qualified 5 V-capable control interface after main rail stable; default disabled |
| 239 | SYS_RESET*, bidirectional OD, 1.8 V | ORIN_SYS_RESET_N; AON-safe receiver owns peripheral enable/decay; never join stack SYS_RESET_N |
| 233 | SHUTDOWN_REQ*, output OD with 5 V pull-up | AON-safe receiver clears run permission; graceful software off is not inherently a fault |
| 214 | FORCE_RECOVERY* | Local ground jumper/test access; exact safe pull-up and boot sequencing per guide |
| 240 | SLEEP/WAKE* | NC initially; no direct stack sleep connection |
| 178 | MOD_SLEEP* | Optional AON-safe monitoring; SC7 disabled in initial software |
| 235 | PMIC_BBAT | NC; IHU supplies time via CAN/STM32/UART |
| 210 | CLK_32K_OUT | Reserved; use only if the selected Wi-Fi card needs a qualified interface |

Separate stack +3V3/+5V pass-through from +3V3_AON, +5V_ORIN,
+3V3_PERIPH and local +1V8_IO. Cameras and M.2 use switched local supplies.
Scratch-study generic power labels must be renamed on integration.

## Three independent CSI inputs

Numbers below name physical module pins, not SoC lane/polarity names. Preserve
physical differential polarity; reconcile NVIDIA SoC swizzles in pinmux/device
tree. Do not transplant the devkit's two-connector overlay as a triple-camera map.

| Camera | CSI port | D0 N / P | D1 N / P | Clock N / P |
|---|---|---|---|---|
| Filter 750 nm | CSI0 | 4 / 6 | 16 / 18 | 10 / 12 |
| Filter 770 nm | CSI1 | 3 / 5 | 15 / 17 | 9 / 11 |
| Filter 780 nm | CSI2 | 22 / 24 | 34 / 36 | 28 / 30 |

For each InnoMaker 15-pin FFC: 1/4/7/10 ground; 2/3 D0 N/P;
5/6 D1 N/P; 8/9 clock N/P; 11 camera power-enable; 12 LED control;
13 SCL; 14 SDA; 15 local switched 3.3 V. Accept contact-side/mating view,
ribbon orientation and exact camera revision before assigning footprint pads.
This is the InnoMaker interface, not the old Raspberry Pi SC0436 assumption.

Module camera I2C SCL/SDA use 213/215 into the camera-only PCA9546A switch.
Three downstream channels separate identical sensor/EEPROM addresses; only
one channel is selected for I2C transactions. Existing module/camera pull-ups
must be inventoried before adding more. Camera enable/LED/reset GPIOs are
allocated during camera-sheet capture and must agree with Linux device tree;
old GPIO127/130/211 assignments are not automatically inherited.

Trigger is generated by STM32, not module GPIO128. Three separate current-capable
outputs connect camera J3 TRIG+/TRIG−; three separate J2 collector/emitter returns
connect supervisor capture inputs through qualified receivers. Header electrical
specification and timing are in [camera and bench validation](camera_and_bench.md).

## UART and recovery

| Module pins | Interface | Use |
|---|---|---|
| 99 TX / 101 RX | UART0, 1.8 V | Application link: STM32 RX receives 99; STM32 TX drives 101 through explicit-direction translator |
| 236 TX / 238 RX | UART2, 1.8 V | Dedicated Jetson console through separate translation; older 203/205 console assignment retired |
| 203/205 | UART1 / boot straps | Reserved; no new external console loading |
| 99 | UART0 TX / RAM-code strap | Translator default high-Z; verify strap load/boot timing before enabling |
| 109 / 111 | USB0 D− / D+ | Recovery data connector; separate from power-only USB-C PD inlet, prevent VBUS back-power |

Do not use automatic-direction TXB circuitry without a separate electrical
acceptance. Initial candidate is SN74AXC2T245 with explicit directions and
common OE, AON 3.3 V to locally switched 1.8 V. Header RX drive cannot power an
unpowered module. Console availability before module reset release needs testing.

## Wi-Fi and fan

Ground-only M.2 Key-E retains PCIe1: module TX N/P 172/174, RX N/P 167/169,
reference clock N/P 173/175, reset 183, clock request 182 and wake 179.
Card TX/RX signal naming and mating-view pad numbering require exact socket
acceptance; the May table is not a checked replacement for that map.
Module USB1 D−/D+ 115/117 may support Bluetooth for the selected card.
No NVMe is added. Use local switched 3.3 V, partial-power-safe controls, and
card-specific SUSCLK/disable configuration. Exact devkit Wi-Fi card is unconfirmed.

Keep ACES 50275-00471-003 four-pin fan connector and devkit mounting/spreader
clearance. Fan interface is ground, 5 V, tach and PWM; verify physical pad order
against the manufacturer/devkit drawing before placement. STM32 owns fan PWM/tach
and full-speed default ground cooling. Flight thermal construction remains open.
Module fan GPIOs 230/208 are not assigned as an additional driver.

## Stack boundaries

| Stack pins | Canonical net | Next-prototype behavior |
|---|---|---|
| H1.51/52 | CAN_A_H/L | Separate populated STM32 CAN-A transceiver |
| H2.49/50 | CAN_B_H/L | Separate populated CAN-B transceiver |
| H2.45/46 | VBAT | Protected stack input with independent AON/main branches; launch isolation still needs system resolution |
| H1.50 | PAYLOAD_EN | Proposed IHU 3.3 V push-pull, default low; hardware hard kill, qualified receiver |
| H2.47 | PAYLOAD_FAULT_N | AON-powered OD driver, IHU-side pull-up; composite latched fault/status semantics |
| H2.48 | PAYLOAD_SLEEP_REQ_N | Reserved or monitored by STM32; no direct Orin routing |
| H1.41/43 | I2C_SDA/I2C_SCL | Pass-through/NC on this carrier; no direct Jetson connection |
| H1.29 | SYS_RESET_N | Reserved stack reset; distinct from ORIN_SYS_RESET_N |

Test points are allocated in the new project; legacy TP refdes are preserved
only in its historical project. Prioritize input branches, AON reset, lock/run
states, main/peripheral rails, POWER_EN, module reset/shutdown and trigger/strobes.
